Предлагаемая концепция модуля

Оптимальная модель для TutorBoard — единый объект координатной плоскости, содержащий произвольное количество графических серий. Каждая серия хранит собственную формулу, тип, область определения, цвет, толщину и видимость.

Такой объект перемещается, масштабируется, копируется, сохраняется и синхронизируется как единая сущность. Отдельные графики редактируются внутри панели свойств.

Текущая архитектура TutorBoard хорошо подходит для этого расширения: объекты представлены дискриминируемым объединением BoardObject, а рендеринг подключается через реестр по kind.

1. Новый объект доски

Предлагаю новый тип:

kind: "math.coordinate-plot"

Пример модели:

export interface CoordinatePlotObject extends BoardObjectBase {
  readonly kind: "math.coordinate-plot";

  readonly size: Size2;

  readonly coordinateViewport: {
    readonly xMin: number;
    readonly xMax: number;
    readonly yMin: number;
    readonly yMax: number;
    readonly equalScale: boolean;
  };

  readonly axes: {
    readonly showXAxis: boolean;
    readonly showYAxis: boolean;
    readonly showArrows: boolean;
    readonly showLabels: boolean;
    readonly xLabel: string;
    readonly yLabel: string;
  };

  readonly grid: {
    readonly visible: boolean;
    readonly majorVisible: boolean;
    readonly minorVisible: boolean;
    readonly automaticStep: boolean;
    readonly xStep?: number;
    readonly yStep?: number;
  };

  readonly legend: {
    readonly visible: boolean;
    readonly position:
      | "top-left"
      | "top-right"
      | "bottom-left"
      | "bottom-right";
  };

  readonly expressionLanguage: "tutorboard-expression/1";

  readonly parameters: readonly PlotParameter[];

  readonly series: readonly PlotSeries[];
}

Обязательное поле style, уже присутствующее у всех объектов доски, можно использовать для оформления рамки и фона координатной плоскости. Каждая линия получает собственный PlotSeriesStyle.

2. Типы графиков
Первая версия
Явная функция
y = f(x)

Примеры:

y = x^2
y = sin(x)
y = 1 / x
y = sqrt(4 - x^2)

Модель:

export interface ExplicitPlotSeries {
  readonly id: PlotSeriesId;
  readonly kind: "explicit";

  readonly name: string;
  readonly expression: string;

  readonly domain: {
    readonly min: number | null;
    readonly max: number | null;
  };

  readonly visible: boolean;
  readonly style: PlotSeriesStyle;
}

При min: null или max: null используется текущий диапазон координатной плоскости.

Параметрическая кривая
x = f(t)
y = g(t)

Примеры:

x(t) = 3 cos(t)
y(t) = 3 sin(t)
0 ≤ t ≤ 2π
x(t) = sin(3t)
y(t) = sin(4t)
0 ≤ t ≤ 2π

Модель:

export interface ParametricPlotSeries {
  readonly id: PlotSeriesId;
  readonly kind: "parametric";

  readonly name: string;
  readonly xExpression: string;
  readonly yExpression: string;

  readonly parameterName: "t";

  readonly range: {
    readonly min: number;
    readonly max: number;
  };

  readonly closed: boolean;
  readonly visible: boolean;
  readonly style: PlotSeriesStyle;
}

Параметр closed помогает корректно соединять начало и конец окружностей, эллипсов и замкнутых кривых.

Последующие версии

Архитектура должна позволять добавить:

type PlotSeries =
  | ExplicitPlotSeries
  | ParametricPlotSeries
  | PolarPlotSeries
  | ImplicitPlotSeries
  | PointSeries
  | InequalitySeries;

Будущие варианты:

полярные графики r = f(φ);
неявные кривые F(x, y) = 0;
системы точек;
интервалы и лучи;
области решений неравенств;
кусочно заданные функции;
графики последовательностей;
касательные, секущие и производные.
3. Несколько графиков на одной плоскости

Поле series является массивом:

readonly series: readonly PlotSeries[];

Пример:

series: [
  {
    id: "series-1",
    kind: "explicit",
    name: "Парабола",
    expression: "x^2",
    domain: { min: null, max: null },
    visible: true,
    style: {
      stroke: "#2563eb",
      strokeWidth: 3,
      strokeStyle: "solid",
      opacity: 1,
    },
  },
  {
    id: "series-2",
    kind: "explicit",
    name: "Синусоида",
    expression: "2 * sin(x)",
    domain: { min: null, max: null },
    visible: true,
    style: {
      stroke: "#dc2626",
      strokeWidth: 3,
      strokeStyle: "solid",
      opacity: 1,
    },
  },
  {
    id: "series-3",
    kind: "parametric",
    name: "Окружность",
    xExpression: "3 * cos(t)",
    yExpression: "3 * sin(t)",

      min: 0,

      strokeStyle: "dashed",

Каждая серия должна поддерживать:

включение и выключение;
изменение порядка;
индивидуальный цвет;
индивидуальную толщину;
сплошной, пунктирный и штрихпунктирный стиль;
подпись в легенде;
дублирование;
удаление;
временное выделение линии при наведении на строку серии.
4. Интерфейс пользователя
Добавление координатной плоскости

На панели инструментов появляется кнопка:

График

После выбора пользователь растягивает прямоугольную область на холсте. Можно также создавать плоскость стандартного размера, например 640 × 420.

Панель редактирования

Панель состоит из трёх разделов.

Можно предусмотреть именованные числовые параметры:

b = 1

Тогда пользователь сможет строить:

y = a*x^2 + b

Параметры будут общими для всех серий одной плоскости. В дальнейшем к ним можно добавить ползунки и анимацию.

5. Режимы взаимодействия

У координатной плоскости возникает конфликт между преобразованием объекта и изменением внутреннего масштаба. Его следует разрешить двумя режимами.

Обычный режим
перетаскивание двигает весь объект;
маркеры Transformer изменяют размер;
вращение доступно через стандартный механизм TutorBoard;
колесо управляет масштабом всей доски.
Режим редактирования графика

Вход:

двойной щелчок по координатной плоскости;
клавиша Enter после выделения;
кнопка «Редактировать график».

В этом режиме:

перетаскивание внутри плоскости изменяет внутренний диапазон координат;
колесо масштабирует координатную систему;
Shift + колесо изменяет только горизонтальный диапазон;
Alt + колесо изменяет только вертикальный диапазон;
щелчок по линии выделяет соответствующую серию;
Escape завершает редактирование.

На рамке объекта следует показывать подпись:

Редактирование координатной плоскости

AST следует держать в оперативном кэше. Это упростит миграции формата документа.

7. Построение плавных графиков

Фиксированного шага недостаточно: на резких поворотах возникает ломаная, а на спокойных участках создаётся лишнее количество точек.

Следует применять адаптивную дискретизацию в экранных координатах.

Явная функция
Берётся начальный набор значений x.
Для каждого отрезка вычисляются значения в начале, середине и конце.
Сравнивается реальная средняя точка графика с серединой хорды.
При отклонении более 0,5–0,75 px участок делится пополам.
Деление продолжается до достижения требуемой точности или лимита глубины.
Параметрическая кривая

Для интервала [t₁, t₂] вычисляются:

P₁ = (x(t₁), y(t₁))
Pm = (x((t₁+t₂)/2), y((t₁+t₂)/2))
P₂ = (x(t₂), y(t₂))

Сегмент делится, когда:

средняя точка заметно отклоняется от хорды;
угол между соседними касательными слишком велик;
сегмент занимает много экранных пикселей;
обнаружена петля или резкий поворот;
одно из значений перестало быть конечным.

Это особенно важно для:

окружностей;
циклоид;
астроид;
фигур Лиссажу;
петель;
кривых с точками возврата.
Разрывы

Для 1/x, tan(x) и подобных функций нельзя соединять две удалённые точки одной линией.

Новый фрагмент кривой начинается, когда:

значение стало NaN или Infinity;
экранный скачок превышает заданный порог;
между соседними точками обнаружена вертикальная асимптота;
функция вышла далеко за пределы видимой области.

Результат рендеринга:

readonly segments: readonly (readonly Vec2[])[];

Каждый сегмент отображается отдельной линией Konva.

8. Координатная сетка

Шаг сетки должен вычисляться автоматически по ряду:

1, 2, 5 × 10ⁿ

Целевой интервал между основными линиями:

60–100 экранных пикселей

Например:

при диапазоне [-10; 10] шаг может быть 2;
при диапазоне [-1; 1] — 0,2;
при диапазоне [-1000; 1000] — 200.

Дополнительно:

нулевая ось рисуется толще;
подписи ограничиваются разумным числом знаков;
очень малые и большие значения переходят в научную запись;
отрицательный ноль отображается как 0;
подписи около краёв сдвигаются внутрь области.
9. Рендеринг в Konva

Новый renderer регистрируется в существующем KonvaRendererRegistry:

{
  kind: "math.coordinate-plot",
  render(object, context) {
    return <CoordinatePlotRenderer object={object} zoom={context.zoom} />;
  },
}

Текущий реестр уже гарантирует наличие единственного рендера для каждого BoardObjectKind, поэтому графический объект естественно встраивается в существующий адаптер.

Внутренняя структура:

Group — общий transform объекта
└── Rect — фон
└── Group — clipping area
    ├── minor grid
    ├── major grid
    ├── axes
    ├── graph series 1
    ├── graph series 2
    ├── graph series N
    └── selected-point overlay
└── Rect — рамка
└── Group — легенда

Для области графиков используется clipX, clipY, clipWidth, clipHeight.

10. Кэширование и производительность

Текущий селектор сцены уже повторно использует BoardRenderItem, пока ссылки на объект и связанные записи остаются прежними.

Для графиков нужен дополнительный кэш:

cacheKey = hash({
  expression,
  parameters,
  range,
  coordinateViewport,
  plotPixelSize,
  boardZoom,
  samplerVersion,
});

Рекомендуемые лимиты:

до 32 серий на одной плоскости;
до 12 000 точек на одну серию;
до 80 000 точек на весь объект;
до 12 уровней адаптивного деления;
до 16 координатных плоскостей на странице.

Во время ввода формулы:

пересчёт запускается с debounce около 100–150 мс;
предыдущий расчёт отменяется;
сначала строится черновой вариант;
затем выполняется уточнение.

Архитектуру вычислителя стоит сделать чистой и совместимой с Web Worker:

compileExpression(source)
sampleExplicitSeries(...)
sampleParametricSeries(...)

Перенос в worker тогда не затронет доменную модель и renderer.

12. Связь с GeometryOS

Численное построение графиков лучше выполнять локально в TutorBoard. Тогда отображение сохраняет работоспособность без сети и остаётся детерминированным.

GeometryOS можно подключить позднее для преобразования текстовых команд в спецификацию:

Постройте на одной плоскости y=x² и y=2x+3

Результат GeometryOS:

{
  "type": "coordinate_plot",
  "viewport": {
    "xMin": -10,
    "xMax": 10,
    "yMin": -10,
    "yMax": 10
  },
  "series": [
    {
      "kind": "explicit",
      "expression": "x^2"
    },
    {
      "kind": "explicit",
      "expression": "2*x+3"
    }
  ]
}

TutorBoard валидирует этот объект и самостоятельно компилирует формулы.

13. Обработка ошибок

Ошибка одной серии не должна блокировать остальные графики.

В строке проблемной серии показывается:

⚠ Неожиданный символ в позиции 7

На плоскости остальные линии продолжают отображаться.

Типовые сообщения:

Неизвестная переменная q
Пропущена закрывающая скобка
Деление на ноль на части области
Область параметра должна иметь конечные границы
Минимальная граница должна быть меньше максимальной
Достигнут лимит сложности выражения

Ошибки области вычисления вроде sqrt(-1) следует трактовать как отсутствие точки, сохраняя валидные участки кривой.
